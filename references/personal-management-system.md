# 个人管理系统

本文档定义了一套跨平台知识管理规范，覆盖**分类、命名、同步、维护**四个维度。在任意设备、任意平台（文件系统、Notion、ima）上都遵循同一套规则。

---

## 一、设计原则

1. **分类即标签** — 目录名既是文件夹也是标签，在 Notion 里变成数据库属性，在 ima 里变成标题前缀
2. **文件名自描述** — 脱离文件夹后只看文件名也能知道它是什么、什么时候的
3. **目录结构即同步策略** — 看一级目录名就知道该不该同步、同步到哪些设备
4. **规则少、可查、不靠记** — 所有规则写在这一份文档里

---

## 二、分类架构

十类按重要程度排列：根基 → 源头 → 主业 → 成长 → 表达 → 工具 → 保障 → 体验 → 扩展。

| 编号 | 分类 | 定位 | 示例内容 |
|------|------|------|----------|
| `00` | 个人档案 | 身份根基 | 证照学历、党籍 |
| `01` | 教育经历 | 学术源头 | 本科课程项目、硕士论文 |
| `02` | 工作经历 | 职业经历 | `XX公司/业务方向/` `XX公司/项目A/` |
| `03` | 学习笔记 | 笔记空间 | 环境配置、编程开发、AI-ML、论文研究、工作日志等 |
| `04` | 思考创作 | 思想表达 | 博客、随笔、反思 |
| `05` | 参考资料 | 知识库存 | 书籍、论文、工具手册 |
| `06` | 健康医疗 | 身体底牌 | 体检报告、病历 |
| `07` | 财务管理 | 经济保障 | 投资记录、保单 |
| `08` | 生活记录 | 人生体验 | 照片、旅行 |
| `09` | 个人项目 | 个人扩展 | 个人作品、独立项目 |
| `99` | 大型文件 | *(存储层，排最后)* | 视频、安装包、备份 |

### 关键约定

- **工作按公司分**：`02-工作经历/` 下每家公司一个独立目录，雇佣人事（股权、绩效、报销）跟公司走。换工作时整个公司目录归档。
- **子目录命名**：有先后顺序的用 `数字前缀-名称`（如 `01-方向A/`），独立容器直接用名称（如 `项目A/` `参考论文/`）。
- **大文件分离**：`99-大型文件/` 为纯存储层，不属于分类体系，不参与同步。50MB 以上的文件放此处，在分类目录中用 `.link.md` 占位索引。

## 三、命名规范

### 3.1 目录命名

| 情况 | 规则 | 示例 |
|------|------|------|
| 有逻辑顺序 | `数字前缀-名称` | `01-方向A/` `02-方向B/` |
| 日期分组 | `YYYY-MM` | `2022-12/` `2023-11/` |
| 独立容器 | 直接用名称 | `项目A/` `工具B/` `参考论文/` |

数字间隔使用 `01, 02, 05...`，方便未来在中间插入新类别。

### 3.2 文件命名

| 类型 | 规则 | 示例 |
|------|------|------|
| **A. 自己产出的文档** | `YYYYMMDD-描述[-v版本].扩展名` | `20230715-项目进度跟踪.xlsx` |
| **B. 下载的参考资料** | **按资料实际标题命名**（从 PDF 元数据或正文提取，不保留下载时的随机文件名） | `某领域综述2024.pdf` |
| **C. 官方文件** | **保留原名**（有法律效力，原名是身份一部分） | `张三-2024下半年绩效评价表-签名版.pdf` |
| **D. 代码项目** | **不改**（遵循项目自身命名规范） | |

## 四、同步架构

### 4.1 同步单元定义

将目录拆分为独立的同步单元，每个单元可以选择同步到不同的设备组合：

| 同步单元 | 覆盖目录 | 同步方式 | 同步设备 |
|----------|----------|----------|----------|
| `档案` | `00-个人档案/` | **不同步** | 仅本地 |
| `教育` | `01-教育经历/` | 网盘 | 全设备（只读归档） |
| `工作` | `02-工作经历/XX公司/` | Syncthing / 网盘 | 公司电脑 + 家里电脑 + 服务器 |
| `代码项目` | 各分类下的独立 Git 仓库 | Git | 按需 |
| `笔记` | `03-笔记空间/` | 网盘 | 全设备 |
| `参考-文档` | `05-参考资料/01~03` | Syncthing / 网盘 | 全设备 |
| `参考-视频` | `05-参考资料/04-视频资料/` | Syncthing / 网盘 | 仅家里 + 服务器 |
| `健康` | `06-健康医疗/` | **不同步** | 仅本地 |
| `财务` | `07-财务管理/` | **不同步** | 仅本地 |
| `生活` | `08-生活记录/` | 网盘 | 全设备 |
| `副业` | `09-个人项目/` | 按项目决定 | — |

### 4.2 差异化同步实现

**原则：目录结构即策略。** 需要不同同步范围的，拆成不同子目录，在 Syncthing 中作为独立文件夹添加。

```
05-参考资料/
  ├── 01-书籍/          ─┐
  ├── 02-论文/           ├─ Syncthing 文件夹：参考-文档 → 全设备
  ├── 03-工具手册/      ─┘
  └── 04-视频资料/      ─── Syncthing 文件夹：参考-视频 → 仅家里+服务器
```

**公司电脑的额外过滤**：在 Syncthing Web UI → 对应文件夹 →「忽略模式」中按需添加：

```
// 公司电脑不想收的文件类型（仅此设备生效，不同步到其他设备）
*.mp4
*.iso
*.dmg
```

> `.stignore` 文件会被同步到其他设备，因此不适合做单设备差异化。**Web UI 忽略模式**才是每台设备独立生效的。

### 4.3 大文件处理

根目录下 `99-大型文件/` 是纯存储层，不参与同步，不属于分类体系：

```
99-大型文件/
  ├── 视频/
  ├── 安装包/
  └── 备份/
```

| 文件大小 | 放哪里 | 分类目录留什么 |
|----------|--------|---------------|
| < 50MB | 直接放对应分类目录 | 文件本身 |
| 50MB–500MB | `99-大型文件/` | `.link.md` 占位文件 |
| > 500MB | 移动硬盘 / NAS | `.link.md` 占位文件 |

占位文件模板（放在分类目录中）：

```markdown
# [文件名]
- 实际位置：99-大型文件/视频/某课程-基础篇.mp4
- 大小：2.1 GB
- 来源：B站已下载
- 说明：XXX 教授机器学习课程第一讲
```

所有同步工具排除 `99-大型文件/` 目录。用 `find . -name "*.link.md"` 可列出全部外部大文件索引。

### 4.4 同步工具速查

| 工具 | 适用场景 | 特点 |
|------|----------|------|
| **Syncthing** | 公司 ↔ 家里 ↔ 服务器 | 点对点、无中心服务器、免费、数据不出机房 |
| **网盘客户端**（OneDrive / iCloud / 百度） | 个人多设备 | 有云端中转、跨平台客户端完善 |
| **Git** | 代码项目 | 版本管理，工作目录下的独立仓 |
| **rsync** | 服务器 ↔ 本地 | 一次性批量同步 |

选择建议：代码用 Git，文档用 Syncthing 或已有网盘，个人档案不同步。

## 五、跨平台映射

同一套分类名，在不同平台上以不同形态出现。

### 文件系统（Linux / Windows / macOS / 服务器）

```
02-工作经历/XX公司/项目A/参考论文/某论文.pdf
```

### Notion

创建数据库，每条记录对应一个文件：

| 属性 | 类型 | 示例 |
|------|------|------|
| 一级分类 | Select | `工作经历` |
| 二级分类 | Select | `项目A` |
| 三级分类 | Select | `参考论文` |
| 日期 | Date | `2024-03-15` |
| 类型 | Select | `论文` `笔记` `数据` `官方文件` |
| 来源 | Select | `本地` `服务器` `Notion` `ima` |
| 链接 | URL | 文件路径或网盘链接 |

### ima（微信笔记）

标题前缀扁平索引：

```
[工作经历/XX公司/项目A/参考论文] 某论文 — 阅读笔记
[笔记空间] 某技术原理详解
[参考资料/论文] 某领域综述 — 阅读笔记
```

## 六、日常操作指南

### 新增内容

1. **定分类** — 属于哪个一级？哪个二级？三级要不要？
2. **命名** — 自己产出的：`YYYYMMDD-描述.扩展名`；下载的/官方的：保留原名
3. **放对位置** — 文件系统放对应目录，Notion 打对应标签，ima 加标题前缀
4. **确认同步** — 检查是否放入了对应同步单元的目录

### 查找内容

- **文件系统**：按目录层级逐级进入，或直接 `find` / Spotlight 搜文件名
- **Notion**：按分类属性筛选数据库
- **ima**：搜索 `[分类名]` 前缀

### 定期维护

- 每季度清理过期中间文件（如实验截图、临时导出数据）
- 每年归档一次不再活跃的项目（移入年份归档目录）
- 新增分类时更新本文档
- `00-个人档案/` 保持只增不减（身份文件永久保留）

## 八、Skill 同步规则

**Skill 与 README 必须同步更新。** 任何改动需要同时更新以下文件：

1. `个人管理系统/README.md`（本文）
2. `~/.claude/skills/personal-management-system/references/personal-management-system.md`
3. `~/.claude/skills/personal-management-system/SKILL.md`（如涉及规则变更）

修改后执行：

```bash
cd ~/.claude/skills/personal-management-system
git add -A && git commit -m "描述" && git push
```

再 `rsync` 到服务器（地址由用户提供），确保三端一致。

技能启动时会自动用 `diff` 检查 README 和 reference 文件是否一致，不一致则自动以较新的为准同步。
